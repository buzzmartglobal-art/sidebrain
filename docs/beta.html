Read this before you install the beta

Sidebrain is early beta software, free to use while we test it. Nothing here is hidden behind a paywall and nothing is for sale — what we want back is a precise description of what broke.

The deal: version 1.1.0 is a working Safari sidebar with real limits, several of them architectural and not fixable by a patch. If those limits are acceptable to you, installing takes about three minutes and bug reports go straight to the developer.

Known issues — the honest list

These are not bugs we are about to fix next week. Some are a consequence of how Safari works.

LimitWhat it means for you
No native right-hand dock Safari's extension APIs do not expose a persistent page-docked panel, so Sidebrain is a userscript that draws its own panel inside the page. It will not appear on PDFs, image-only pages, or sites that block injected scripts, and a site with aggressive layout scripts can push it around.
You install an extension, not an app There is no App Store download. You install the free Userscripts extension, allow it on the sites you want, and drop sidebrain.user.js into the folder it shows. If Safari disables the extension after an update, the panel disappears until you re-enable it.
Pro needs a local Node service Routing, memory, channel self-check and free web search run in a small service under ~/ai-gateway. It must be started and left running. If it stops, the panel keeps answering but loses routing and memory, and the footer shows the fallback channel.
Subscription channels are off by default Using your ChatGPT or Claude plan through the official CLI is a switch you have to turn on, and whether that use fits your agreement with the provider is your call, not ours. We only invoke a CLI you installed and logged in yourself. We never proxy, resell or pay for quota.
macOS only No iOS, no iPad, no Chrome, no Windows. No sync of memory between two Macs — the memory file is local, which is the point, and also the limitation.
Single developer, no support desk Expect a reply in the issue tracker rather than by email. Features you ask for may take weeks or never arrive; the issue label tells you which is likely.

How to report a problem

One issue per problem, opened on GitHub. These five details are the difference between a fix and a shrug.

  1. Version. The exact build, e.g. 1.1.0. It is shown at the top of the panel's settings (⚙︎) and in the userscript header. "Latest" is not a version.
  2. Your macOS and Safari versions. Apple menu → About This Mac, and Safari → About Safari. The beta is tested on macOS 26.5 / Safari 26.5; anything else is genuinely useful data.
  3. Which channel you installed. Free edition only, or free edition plus the local Pro service? And which provider answered — the panel footer under the last reply names the channel, the latency and the cost.
  4. What the footer showed, and what you expected. Copy the footer line verbatim if you can: it carries the channel, the model, the latency and the cost, which is usually enough to tell a routing bug from a quota bug from a key bug.
  5. Steps to reproduce. The URL if the site is public, what you typed, and whether it happens every time. A screen recording beats three paragraphs.

Which feedback is actually worth your time

Ranked by how much it changes the next build, not by how nice it is to hear.

Most useful

A specific break

"On this URL, pressing ⇧⌘K does nothing after the page loads." Site name, Safari version, footer line. Ten of these are worth more than a hundred "love it" replies.

Very useful

Where the routing guessed wrong

If a question went to a paid channel when a free one was available, or fell back silently, the footer line says so. That is the core of the product and the hardest part to test alone.

→ bug template, include footer
Useful

The thing you stopped using it for

"I opened it twice and went back to copy-pasting into ChatGPT" is a real finding. Tell us which step lost you: install, first key, the panel itself, or memory.
